# Agent working rules

## Stack

pnpm + TypeScript + React + Vite + Tailwind v4 + shadcn/ui, with a
Cloudflare Worker backend ("Workers with static assets" via
@cloudflare/vite-plugin, config in wrangler.jsonc). Tested with Vitest (unit:
`src/`, `worker/`, `shared/`) and Playwright (e2e: `e2e/`), linted with
ESLint, formatted with Prettier.

- TypeScript runs side-by-side per the official TS 7 guidance: `tsc` (and
  `pnpm typecheck`) is the native TS 7 compiler via the `@typescript/native`
  alias, while the `typescript` package is aliased to
  `@typescript/typescript6` because typescript-eslint requires the TS 6 API.
  Do not "simplify" this to a single `typescript` dependency.
- TS 7 removed `baseUrl`; keep `paths` entries relative to the repo root.
- Three TypeScript projects: `tsconfig.app.json` (src + shared, DOM lib),
  `tsconfig.worker.json` (worker + shared, Workers runtime types from the
  generated `worker-configuration.d.ts`), `tsconfig.node.json` (configs,
  e2e, scripts, plus `shared/types.ts`). `shared/` must stay
  runtime-agnostic: no DOM, no Workers globals, no React.
- `worker-configuration.d.ts` is generated by `wrangler types` (gitignored);
  `pnpm typecheck` regenerates it. The Worker's bindings are declared by
  hand in `worker/env.ts` because secrets are unknown to `wrangler types`
  without `.dev.vars`.
- Vitest runs with globals off; always import `describe`/`it`/`expect` from
  `vitest`. Worker tests start with `// @vitest-environment node` so
  WebCrypto and `Response` are Node's. Tests that touch Dexie import
  `fake-indexeddb/auto` first.
- `vitest.setup.ts` registers Testing Library `cleanup()` explicitly; do not
  remove it, or rendered components leak across tests.
- Add shadcn/ui components with `pnpm dlx shadcn@latest add <component>`.

## Workflow

After making changes from a prompt and BEFORE committing:

1. Author new tests covering the changes being made.
2. Update any documentation affected by the changes (README, this file).
3. Run `pnpm format-and-validate` and repair any regressions in-line. This
   includes the Playwright e2e suite; never skip it.

Commit in small, modular units (one logical change per commit).

## Product invariants

- **The token never reaches the browser.** OAuth completes in the Worker;
  the token lives only in the AES-GCM-sealed HttpOnly `prismy_session`
  cookie (`worker/session.ts`) and GitHub is called only through
  `POST /api/github/graphql`. Never return the token to the client, log it,
  or add a client-side GitHub call. POST routes require the app's `Origin`.
- **The Worker is stateless and free to operate.** No KV, D1, Durable
  Objects or paid features. All PR data lives in the visitor's IndexedDB
  (`src/db/schema.ts`, one database per login).
- **Sync is resumable and incremental.** `shared/sync/engine.ts` writes every
  page through and persists `pendingSlices`; an aborted run leaves the store
  resumable. Later runs search `updated:>=lastSyncAt-1h` and refresh stale
  open PRs by id. Changing the engine means extending `engine.test.ts`, which
  drives it against an in-memory GitHub.
- **Partial data is always labelled.** A capped repo or a day over the
  1,000-result search limit sets `truncated`; the UI shows `CoverageBanner`.
  Repo caps are newest-first so the effective window is the same for every
  contributor.
- **Metrics are pure.** Everything in `shared/metrics` takes `PrRecord[]` and
  a `TimeWindow` and is unit-tested in `metrics.test.ts`. Windows are
  half-open `[from, to)`; "merged" means `mergedAt` in the window, "opened"
  means `createdAt` in it; weeks start Monday 00:00 UTC.
- **One filter row.** The window selector and sync chip sit in the header
  (`AppShell` `controls`) and scope every number on the page. The window is
  the `?window=` query parameter; nothing else is per-chart.
- **Chart rules** (see `src/index.css` and `src/components/charts`): series
  colours are the `--chart-*` tokens only, assigned in fixed order (repo
  series fold past seven into "Other"); "you" is `--chart-accent` and context
  is `--chart-muted`; bars ≤ 24px with rounded data ends; hairline solid grid;
  a legend whenever two or more series; a tooltip on every mark; and every
  chart ships in `ChartCard`, which carries its table view. Status colours
  are never used for series. Run the dataviz palette validator on any new
  categorical colour in both modes.
- **Light and dark themes.** The theme is the `dark` class on `<html>`;
  `index.css` defines light tokens on `:root` and dark ones on `.dark`, so
  every colour must come from a token (or a `dark:` variant). An inline
  script in `index.html` applies the theme before first paint and mirrors
  `src/lib/theme.ts` (key `prismy:theme`, media query, theme-color values):
  change both together. `e2e/theme.spec.ts` checks the script works without
  the app.
- **E2e is hermetic.** Specs call `stubSession` / `stubGraphql`
  (`e2e/fixtures.ts`) so no run reaches GitHub; `acme/big` in the fixture
  exercises the partial-data path.
- Mobile-friendly: page padding is the `safe-x` utility; the e2e specs guard
  against horizontal scroll.

## Gotchas

- `assets.run_worker_first` is `true` and `not_found_handling` is
  `single-page-application`, so `/repo/:owner/:name` deep links serve
  `index.html`; the Worker only handles `/api/*`.
- `useWindow` resolves "now" once per window key so every metric on a page
  shares one clock; `useSync` chains runs per database+source so React
  StrictMode's double effect cannot interleave two syncs.
- The chart pages are lazy (`src/App.tsx`) so the landing page doesn't load
  Recharts; `vite.config.ts` raises the chunk-size warning accordingly.
- `wrangler preview` (the PR preview workflow) fails unless `wrangler.jsonc`
  has a `previews` block; keep the empty `"previews": {}`.
- `public/og.png` and `public/apple-touch-icon.png` are generated
  (`pnpm og`, `scripts/og/render.ts`); regenerate them instead of editing the
  PNGs.
- lucide-react has no brand icons; the GitHub mark is
  `src/components/github-icon.tsx`.
